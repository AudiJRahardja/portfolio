Sehat Bersama AI

Indonesian/English health-information chatbot on the Gemini API: prompt-engineered replies, emergency keyword warnings and a clear "not a diagnosis" disclaimer.

Dec 2025

The problem

People look up health questions online and get answers that are hard to read or that sound like a diagnosis. This chatbot answers basic health questions in plain Indonesian or English, never gives a firm diagnosis or prescription doses, and points to 119 / 112 when a message sounds like an emergency.

How it works

6 stages. Pick a stage to see what goes in, what happens and what comes out. Arrow keys move between stages.

Stage 01 of 06

Type a question

Done
Input

A health question typed in Indonesian or English

Operation

The page adds it to the chat history and sends only the real user and AI turns to the server

Output

Up to the last 20 messages as { role, text }

  • The interface switches between Bahasa Indonesia and English, and has a dark mode.
  • Chat history stays when the page is refreshed.

Flow: script.js >> toApiMessages >> POST /api/chat

Stage 02 of 06

Emergency check

Done
Input

The user's own message

Operation

Match it against Indonesian and English emergency phrases (chest pain, can't breathe, fainting, seizures, stroke signs, self-harm)

Output

An instant warning to call 119 or 112, shown before the AI reply

  • Runs in the browser, so the warning does not depend on the AI answering.
  • Self-harm messages get their own warning, separate from medical emergencies.

Flow: detectEmergency(message) >> "mental" | "medical" | null >> alert

Stage 03 of 06

Check request

Done
Input

The chat history from the browser

Operation

Reject empty or too-long messages, merge repeated turns, and limit how often one IP can ask

Output

A clean, alternating conversation that ends with a user turn

  • Limits: 2,000 characters per user message, 20 messages of history, 10 messages per minute per IP.
  • Long earlier AI replies are shortened to 4,000 characters instead of being rejected.

Flow: rateLimiter >> parseMessages >> { messages }

Stage 04 of 06

Ask Gemini

Done
Input

The conversation plus a fixed system prompt

Operation

Send it to Gemini (gemini-2.5-flash by default) and stream the reply back

Output

Answer text in small chunks

  • The system prompt: stay on health topics, no firm diagnosis, no prescription doses, reply in the language of the latest message, and urge 119 / 112 for emergency signs.
  • Overload and network errors are retried, but only before the reply starts; there is a timeout and the request is cancelled if the user leaves.

Flow: buildGeminiBody >> createGeminiClient.stream >> readSSE >> interpretChunk

Stage 05 of 06

Stream reply

Done
Input

Streamed chunks from Gemini

Operation

Forward each chunk to the browser and draw it as safe Markdown, word by word

Output

The reply on screen, with a "not a diagnosis" disclaimer and a stop button

  • The Markdown renderer escapes all HTML, so a reply cannot inject markup into the page.
  • Blocked, empty or cut-off replies end with a notice that explains what happened.

Flow: {type:"chunk"} ... {type:"done", notice} >> splitSSE >> renderMarkdown

Stage 06 of 06

Feedback

Done
Input

A thumbs up or down on a reply

Operation

Save the rating with the AI reply

Output

One line in backend/data/feedback.jsonl

  • Only the AI reply and its rating are stored, never the user's question.

Flow: POST /api/feedback >> appendFile(feedback.jsonl)

Results so far

There is no evaluation of answer quality: the project has no test set of health questions with checked answers, so there are no accuracy numbers.

  • 29 automated tests 29 checks run without calling Gemini, so they cost no API quota. node:test, with a fake model: server routes, request checks, streaming, safe Markdown and emergency detection Source: backend/test/
  • 119 / 112 emergency numbers shown on risky messages If a message mentions chest pain, fainting or self-harm, the page tells the user to call for help right away. Keyword check in the browser plus a rule in the system prompt Source: frontend/lib.js
  • 10 / min chat messages allowed per IP Stops one person from using up the shared AI quota. Also: 2,000 characters per message, 20 messages of history Source: README.md

What I learned

  • Safety-critical behaviour should not depend on the model. The emergency warning is a keyword check on the user's own message, so it shows instantly even if Gemini is slow, busy or blocked.
  • Streaming changes error handling: a failure before the first chunk is a normal JSON error with its HTTP status, a failure after that has to arrive as an error event inside the stream.
  • Privacy by default: feedback keeps only the AI reply and the rating, not what the user asked.
