Performance Decay Rate (PDR): IEEE paper

How badly do ML models break when tabular data gets noisy? A new metric that separates a model's structural fragility from its baseline accuracy.

May – Sep 2026

Paper (IEEE Xplore) (opens in a new tab)Code (opens in a new tab)

The problem

Models are usually evaluated only on clean data. Real-world inputs come from imperfect sensors and messy databases, so we rarely know how fragile a model really is.

My part

First author: main researcher and lead writer. Designed the method and degradation framework, implemented all four models, ran the evaluations, and wrote the analysis, conclusion, slides and video.

How it works

6 stages. Pick a stage to see what goes in, what happens and what comes out. Arrow keys move between stages.

Stage 01 of 06

Load dataset

Done
Input

The UCI Heart Disease dataset (Kaggle copy, heart_disease.csv)

Operation

Load the 13 patient features and the heart-disease label, and check missing values and class balance

Output

1,025 rows: 526 with heart disease, 499 without, no missing values

  • Five continuous features get the noise later: age, resting blood pressure, cholesterol, maximum heart rate and ST depression.
  • Chosen because medical data is prone to faulty sensors and data-entry errors.

Flow: read_csv(heart_disease.csv) >> describe >> class balance

Stage 02 of 06

Split & scale

Done
Input

The full table

Operation

Make a 70 / 30 train / test split and standardise the continuous features with a scaler fitted on the training part only

Output

One train and one test set per run, repeated 25 times with a new split each time

  • 25 runs (split seeds 42 to 66), and every score is the mean over the runs, so one lucky split cannot decide the result.
  • A fixed 70 / 30 split instead of k-fold, so fold differences do not mix with the effect of the noise.

Flow: train_test_split(test_size=0.3, seed=42+i) >> StandardScaler.fit(train)

Stage 03 of 06

Inject AWGN

Done
Input

The scaled train and test sets

Operation

Add Gaussian noise to each continuous feature, with a standard deviation of 0% to 50% of that feature's own spread, in 10% steps

Output

Six versions of the data per run: clean, then 10, 20, 30, 40 and 50% noise

  • Additive white Gaussian noise imitates a faulty sensor that gives slightly wrong readings.
  • The same noise function is used for training data and for test data, depending on the scenario.

Flow: add_awgn_noise(data, level, continuous_cols) for level in 0.0 … 0.5

Stage 04 of 06

Train two ways

Done
Input

Clean and noisy versions of each split

Operation

Fit MLP, Random Forest, XGBoost and SVM twice per noise level: trained on noisy data and tested on clean, then trained on clean and tested on noisy

Output

Predictions and probabilities for 4 models × 2 scenarios × 6 noise levels × 25 runs

  • "Train clean, test noisy" imitates a model built in the lab and deployed on messy real data.
  • "Train noisy, test clean" checks whether noise during training hurts the model or helps it.
  • Models: Random Forest, XGBoost, SVM (RBF, with probabilities) and an MLP (up to 500 iterations).

Flow: for model in (RF, XGB, SVM, MLP): fit(noisy) >> predict(clean) ; fit(clean) >> predict(noisy)

Stage 05 of 06

Score & PDR

Done
Input

Predictions at every noise level

Operation

Compute accuracy, precision, recall, F1, MCC and AUC-ROC, then the Performance Decay Rate: the drop from the model's own clean score, as a percentage of that score

Output

A table of every metric and its decay rate per model, scenario and noise level

  • PDR = (clean score − noisy score) / clean score × 100%.
  • Because it divides by the model's own starting score, a strong model and a weak model can be compared on how much they lose, not only on where they end up.

Flow: get_metrics >> groupby(model, scenario, level).mean() >> calculate_decay >> robustness_metrics_full.csv

Stage 06 of 06

Compare & publish

Done
Input

The averaged metrics and decay rates

Operation

Plot degradation curves and decay bars, pick out the 0%, 20% and 50% points, and write up which models break and why

Output

The ICORIS 2026 paper (IEEE Xplore), slides and a presentation video

  • XGBoost lost the most (17.03% MCC); Random Forest held up best of the strong models (12.12%).
  • SVM lost under 2%, but only because it started much lower (MCC 0.766).

Flow: plot_combined_degradation >> plot_decay_comparison >> table1 / table2 >> paper

What I learned

  • A model's clean-data score can hide how fragile it is: XGBoost and MLP started near the top and lost the most once the inputs were noisy.
  • A small drop can be misleading. SVM barely moved because it never learned the clean data well, which is why PDR is read next to the starting score, not alone.
  • Noise during training worked like regularisation for the MLP (9.63% decay vs 12.85%), so adding noise on purpose is a cheap way to toughen a neural network.

What's next
