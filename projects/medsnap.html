MedSnap

Point your phone at a medicine box: on-device OCR finds the active ingredients and dosages, even on blurry, tilted or sideways labels.

Apr – Oct 2026

Live demo (opens in a new tab)Code (opens in a new tab)

The problem

Medicine labels are small, glossy and often photographed at an angle. Generic OCR misses ingredients or reads the wrong dose, and you shouldn't have to upload a photo of your medication to a server.

My part

Rebuilt the hackathon prototype on my own: the image pipeline, matching, benchmark and UI.

Solo rebuild · Personal project · started at a hackathon

  • JavaScript
  • Tesseract.js
  • Hand-written image processing
  • Node + Puppeteer bench

How it works

6 stages. Pick a stage to see what goes in, what happens and what comes out. Arrow keys move between stages.

Stage 01 of 06

Capture frame

Done
Input

The live phone camera, a desktop webcam, or an uploaded / dropped photo

Operation

Grab 6 frames 90 ms apart and keep the sharpest one, scored by the variance of the Laplacian

Output

One still frame plus its sharpness score; frames scoring under 150 are flagged as blurry

  • Burst capture means the shake from tapping the button does not blur the shot.
  • Asks for 1080p, continuous autofocus, zoom presets and flash where the phone supports them.
  • A QR code hands the app from a desktop to a phone. The photo never leaves the device.

Flow: startCamera >> captureSharpestFrame >> measureSharpness >> runScan

Stage 02 of 06

Prepare image

Done
Input

The captured RGBA frame

Operation

Pick the clearest colour channel, straighten tilted text, resize and even out the contrast

Output

A level, grayscale image with its long side at about 2000 px

  • Channel choice: luminance or a single R, G or B channel, picked by Otsu between-class variance, so coloured print on a same-brightness background stays readable.
  • Deskew: a projection-profile search from -15 to 15 degrees in 0.5 degree steps. Tilt otherwise splits drug names from their doses.
  • Upscaled images get an unsharp mask; others do not, because sharpening would only add noise.

Flow: toBestGray >> estimateSkew >> deskew >> prepare

Stage 03 of 06

Multi-pass OCR

Done
Input

The prepared image

Operation

Read the label in up to five kinds of pass, stopping as soon as every dose is attached to a known ingredient

Output

Text, word confidences and the medicines found by each pass

  • Pass order: plain grayscale, a zoom-in on small print (words under 28 px tall), an adaptive threshold for glare and shadows, inverted colours, then 90 degree turns for sideways text.
  • A watchdog restarts the OCR worker if a pass hangs, and cancel is instant.
  • All image code is written by hand; Tesseract only does the character recognition.

Flow: runPipeline >> pass(grayscale) >> pass(zoom) >> adaptiveThreshold >> invert >> rotateGray

Stage 04 of 06

Match drugs

Done
Input

Raw OCR text from every pass

Operation

Fix OCR typos against a drug dictionary, clean up doses and pair each ingredient with its dose

Output

A merged list of ingredients with doses, plus words that could not be matched

  • Dictionary: 225 generic drug groups (English and Indonesian spellings) and 118 Indonesian brands.
  • OCR-aware matching (rn to m, 0 to o, l and I) that only takes the closest name, so Amoxicillin is not read as Ampicillin.
  • Doses like "5OO rng" become "500 mg". A dose whose unit was lost to glare shows as "500 (unit unclear)" instead of a guess.

Flow: cleanOcrText >> findDrugNames >> findDosages >> extractMedications >> mergeMeds

Stage 05 of 06

Show results

Done
Input

The matched ingredients and doses

Operation

Show one card per ingredient and fetch a short drug summary on request

Output

A results sheet, saved to the scan history on the device

  • Cards show the dose, a "Read as ..." note when a typo was corrected, and low-confidence words highlighted.
  • Drug summaries come from Indonesian Wikipedia first, then English.
  • Works offline after the OCR model has loaded once.

Flow: renderResults >> medCard >> wikiSummary >> saveToHistory

Stage 06 of 06

Benchmark

Done
Input

Generated medicine labels with a list of the expected ingredients and doses

Operation

Run the exact app pipeline on every label and count what it got right, for the old and new image pipeline

Output

Labels fully read, ingredients found and correct doses per test set

  • Labels are drawn with real fonts, then degraded with blur, noise, glare, shadows, tilt, rotation, clutter and low light.
  • Sets: hard (64 labels, 96 ingredients), easy (42), same-brightness colour (4) and sideways labels.
  • Also text-matching and false-positive checks, and browser tests in Chrome with a fake webcam.

Flow: gen_hard.py >> benchmark.js v2 >> benchmark.js v1 >> e2e.js

Results so far

All test labels are generated, not real photos. Real-world accuracy still needs testing on actual medicine boxes.

  • 64 / 64 hard-set labels read completely Baseline: First image pipeline (v1): 55 / 64 Every one of the 64 hard test labels was read in full. Synthetic hard set: 64 labels, 96 ingredients Source: README.md
  • 91 / 96 correct doses, hard set Baseline: First image pipeline (v1): 72 / 96 About 19 in 20 doses come out right. The misses are labels where glare wiped out the unit. Synthetic hard set Source: README.md
  • 8 / 8 sideways labels read Baseline: First image pipeline (v1): 0 / 8 Text printed sideways on the narrow side of a box is now read. Synthetic sideways labels Source: README.md
  • 42 / 42 easy-set labels read completely Baseline: Original hackathon code: 34 / 42 All 42 simple labels read in full; 41 of 42 doses correct. Synthetic easy set, 42 labels Source: README.md

Caveat: All benchmark labels are generated, not real photos.

What I learned

  • Testing the old and new image pipeline with the same text-correction code showed exactly how much the image work alone added.
  • Straightening the text first mattered: tilted lines made the OCR split a drug name from its dose.
  • When the unit is unreadable, saying "unit unclear" is safer than guessing a dose on a medicine label.

What's next

  • Test accuracy on real photos of medicine boxes, not only generated labels.
