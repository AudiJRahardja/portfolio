VSTravel

A responsive five-page travel website, designed in Figma first and then built by hand.

May 2025

The problem

The HCI lab asked for a multi-page responsive website, designed first and then built by hand. VSTravel is a made-up travel agency: visitors should be able to browse destinations, filter them, and book a trip from a phone or a laptop.

My part

Design and build.

Solo · Course project · Human–Computer Interaction

  • Figma
  • HTML
  • CSS
  • JavaScript

How it works

5 stages. Pick a stage to see what goes in, what happens and what comes out. Arrow keys move between stages.

Stage 01 of 05

Design in Figma

Done
Input

The assignment brief and the five pages the site needs

Operation

Lay out the pages in one Figma file with the site's photos and icons

Output

VSTravel Audi.fig, the design the pages were built from

  • One shared header (logo, nav) and footer (contact, social icons, quick links) on every page.
  • Pages: Home, Destinations, Travel Now, About Us and Contact Us.

Flow: brief >> page layouts >> VSTravel Audi.fig

Stage 02 of 05

Build pages

Done
Input

The Figma layouts

Operation

Hand-code five HTML pages on one shared stylesheet

Output

index, destinations, travel-now, about-us and contact-us pages

  • Colours, shadows, radius and transitions are CSS variables, so the theme is set in one place.
  • About Us has a two-column story, a vertical timeline and core-value cards; Contact Us has office cards and a form.

Flow: index.html · destinations.html · travel-now.html · about-us.html · contact-us.html >> style.css

Stage 03 of 05

Add interactions

Done
Input

The static pages

Operation

Add a mobile menu, a sign-up popup, a destination filter, form checks and a booking-success modal

Output

One script.js shared by all pages

  • The filter matches each card's data-region, data-price and data-activity against three drop-downs, and shows a "no results" message when nothing fits.
  • Form checks are written without regex: name of 3+ characters, an "@" before a ".", at least 10 digits in the phone number.
  • The booking form also checks dates are not in the past, the return date is after departure, and the terms box is ticked.

Flow: mobileMenuBtn >> signUp popup >> filterBtn >> validateName / validateEmail / validatePhone / validateDate >> bookingSuccessModal

Stage 04 of 05

Responsive check

Done
Input

The desktop layout

Operation

Add breakpoints at 768px and 480px; below 768px the nav becomes a slide-in hamburger menu

Output

Pages that fit phone, tablet and desktop widths

  • Every page has the viewport meta tag.

Flow: @media (max-width: 768px) >> nav.active >> @media (max-width: 480px)

Results so far

A course website, so there are no usage or test numbers. The counts describe what was built.

  • 5 pages, designed and hand-built A small complete site, from Figma to working code. Home, Destinations, Travel Now, About Us, Contact Us Source: VSTravel Documentation Audi.docx
  • 6 destinations, 3 filters Visitors can narrow trips by region, price and activity. Filter uses data attributes on each card Source: Audi/VSTravel/destinations.html
  • 10 booking-form checks The form catches mistakes like a return date before departure before it is sent. Name, email, phone, participants, destination, other destination, departure and return dates, accommodation, terms Source: Audi/VSTravel/assets/js/script.js
  • 2 responsive breakpoints The layout changes for tablets and again for phones. 768px and 480px Source: Audi/VSTravel/assets/css/style.css

What I learned

  • A first version of the destination filter hid cards at random; it is still in script.js, commented out. It was replaced by real matching on data attributes plus a "no results" message.
  • Keeping colours, shadows and spacing in CSS variables meant one change updated all five pages.
