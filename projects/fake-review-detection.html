Fake Review Detection

A comparative study of statistical, sequential and transformer models for detecting AI-generated product reviews.

May – Jun 2026

Code (opens in a new tab)

The problem

AI-generated fake reviews are cheap to produce and hard for people to spot. We compared four kinds of models, from word counts to a fine-tuned transformer and a zero-shot LLM, on the same 40,432 Amazon-style reviews to see how much model sophistication actually buys.

My part

Overall planning and pipeline. Trained the DistilBERT model, and took part in the results analysis.

How it works

6 stages. Pick a stage to see what goes in, what happens and what comes out. Arrow keys move between stages.

Stage 01 of 06

Clean & split

Done
Input

40,432 product reviews from a Kaggle dataset: 20,216 computer-generated, 20,216 original

Operation

Clean the text in two ways (lemmatized without stopwords for the classic models, light cleaning for DistilBERT) and make one fixed split

Output

40,428 non-empty reviews: 26,277 train, 6,065 validation, 8,086 test, each 50 / 50 fake and real

  • The split is stratified with seed 42 and saved once, so every model is scored on the same test set.
  • Emojis are turned into words, since they can carry meaning in a review.

Flow: fake_reviews_dataset.csv >> preprocess_reviews >> remove_stopwords | clean_for_bert >> splits.npz

Stage 02 of 06

TF-IDF baseline

Done
Input

Lemmatized, stopword-free training text

Operation

Turn reviews into TF-IDF vectors over the 5,000 most informative terms and fit Logistic Regression

Output

The baseline every other model is compared with: 84.61% F1

  • Trains in 0.2 seconds on a CPU.
  • Its strongest "fake" words were vague, filler and hedging language, not the extreme superlatives the team expected.

Flow: TfidfVectorizer(max_features=5000) >> LogisticRegression >> lr_metrics.pkl

Stage 03 of 06

PosAtt-BiLSTM

Done
Input

Token lists, cut or padded to 100 tokens, with a 20,000-word vocabulary

Operation

GloVe embeddings plus a positional encoding, a two-layer bidirectional LSTM and Bahdanau attention

Output

89.25% F1, with attention weights that show which words drove each decision

  • The positional encoding was shifted from [-1, 1] to [0, 1] (NN-SPE) so it would not interfere with the GloVe vectors.
  • Early stopping at epoch 8; about 5 seconds per epoch and 61 MB of GPU memory.

Flow: load_glove >> NN_SPE >> PosAttBiLSTM >> run_epoch >> predict_bilstm

Stage 04 of 06

Fine-tune DistilBERT

Done
Input

Lightly cleaned review text, tokenized to 256 sub-word tokens

Operation

Fine-tune distilbert-base-uncased for fake vs real, keeping the best checkpoint by validation score

Output

The best model: 97.67% F1 and 99.84% ROC-AUC on 8,086 test reviews

  • My part of the modelling: I fine-tuned and evaluated this model.
  • It misses about 1% of fake reviews and wrongly flags about 4% of real ones (151 false positives, 36 false negatives).
  • About 580 to 630 seconds per epoch, and about 1.1 GB of GPU memory.

Flow: DistilBertTokenizer >> DistilBertForSequenceClassification >> bert_train_epoch >> predict_distilbert

Stage 05 of 06

Zero-shot LLM

Done
Input

A balanced sample of 100 raw reviews (50 real, 50 fake)

Operation

Ask Phi-4-mini to answer FAKE or REAL with a one-sentence reason, with no training at all

Output

64% accuracy and 51.35% F1

  • It leaned towards "real": it caught 45 of 50 real reviews but only 19 of 50 fake ones.
  • About 1.7 seconds per review, so it was only run on 100 reviews.

Flow: build_prompt >> phi_predict_batch >> first word = label >> phase4_metrics.csv

Stage 06 of 06

Web app

Done
Input

Any review text pasted by a user

Operation

Run the fine-tuned DistilBERT model, loaded once when the server starts

Output

A REAL or FAKE verdict with both probabilities, in about 0.5 to 1.5 seconds on a CPU

  • Built by a teammate. The code is on Google Drive, not in the GitHub repo.
  • POST /predict takes {"text": "..."} and returns the label, real_prob and fake_prob.

Flow: POST /predict >> tokenizer >> DistilBERT >> softmax >> verdict card

  • 89.25% F1, PosAtt-BiLSTM Baseline: TF-IDF + Logistic Regression: 84.61% F1 on the same test set Better than counting words, at a fraction of the transformer's memory. Same test set; 61 MB of GPU memory vs about 1.1 GB for DistilBERT Source: 03_bilstm.ipynb
  • 84.61% F1, TF-IDF + Logistic Regression The simple word-count model already gets about 85 in 100 right. The project's baseline; trains in 0.2 seconds Source: 02_tfidf_logistic.ipynb

What I learned

  • Task-specific training data mattered more than model size: the zero-shot Phi-4-mini was 46 F1 points behind the fine-tuned DistilBERT.
  • A smaller model can still be the right choice: the BiLSTM reached 89% F1 with about 61 MB of GPU memory against about 1.1 GB for DistilBERT, and its attention shows which words drove a decision.
  • The test set is 50 / 50, but real platforms have far fewer fakes. The report notes precision drops as fakes get rarer, so the decision threshold must be re-tuned before real use.

What's next

  • Try few-shot and chain-of-thought prompts for Phi-4-mini, then fine-tune it, to see if it can beat DistilBERT.
  • Re-tune decision thresholds for realistic fake-review rates and report precision and recall there.
  • Test on other domains (hotel and restaurant reviews), multilingual reviews and deliberately adversarial fakes.
