LQ45 Stock Direction Predictor

Web app that predicts where each of the 45 LQ45 stocks will be in 14 trading days, with Linear Regression on prices, moving averages and RSI.

Jun 2026

Live demo (opens in a new tab)Code (opens in a new tab)

The problem

Stock prices are noisy and change behaviour suddenly, and a single indicator such as a moving average or RSI is a weak signal on its own. The goal was not a perfect forecast, but a simple, transparent model whose weights can be read, served end to end as a web app for Indonesian LQ45 stocks.

My part

Planned the overall idea and pipeline; did the model, results and metric analysis; built the frontend and login.

How it works

6 stages. Pick a stage to see what goes in, what happens and what comes out. Arrow keys move between stages.

Stage 01 of 06

Prototype & backtest

Done
Input

A Kaggle dataset of 6 US stocks (AAPL, AMZN, GOOGL, META, MSFT, NVDA): 14,964 daily rows, 2016 to 2026

Operation

Fit Linear Regression per stock on the first 80% of days and test on the last 20%, in time order

Output

Backtest R² between 0.66 (AMZN) and 0.91 (GOOGL), plus MAE and RMSE per stock

  • The split is chronological, not random, so the model never sees future prices while training.
  • The team also tried SVR and XGBoost; both got negative R² on most stocks because they cannot predict prices outside the range they were trained on.

Flow: OHLCdataset_ML.csv >> add_features >> split 80 / 20 >> LinearRegression >> MAE · RMSE · R²

Stage 02 of 06

Fetch prices

Done
Input

The 45 LQ45 tickers, grouped into 5 sectors

Operation

Download 5 years of daily prices for each <ticker>.JK from Yahoo Finance, plus P/E, P/B and analyst ratings

Output

One price table per stock; stocks with fewer than 120 days are skipped

  • Sectors: Banking, Commodities, Consumer, Telecom & Tech and Industrial.
  • Analyst ratings are turned into a simple BUY / HOLD / SELL label.

Flow: yf.download(<ticker>.JK, period="5y") >> get_sentiment

Stage 03 of 06

Build features

Done
Input

Daily open, high, low and close prices

Operation

Add 10, 20 and 50-day moving averages and a 14-day RSI; the target is the close 14 trading days later

Output

8 features per day: Open, High, Low, Close, MA10, MA20, MA50, RSI14

  • The prices and moving averages are almost perfectly correlated (0.99 to 1.00); RSI14 is the only feature that adds a different signal.

Flow: compute_features >> MA10 · MA20 · MA50 · RSI14 >> Target = Close.shift(-14)

Stage 04 of 06

Train per stock

Done
Input

The feature table of one stock

Operation

Scale the features and fit one Linear Regression per stock, then predict from the latest day

Output

A predicted price and date, and UP if it is above the last close, DOWN if not

  • Linear Regression was chosen as a transparent baseline: every feature's weight can be read, and it can follow a trend past the prices it was trained on.
  • The deployed training uses all 5 years; the 80 / 20 backtest was only run in the prototype.

Flow: train_ticker >> StandardScaler >> LinearRegression.fit >> predict(last row) >> UP | DOWN

Stage 05 of 06

Publish & serve

Done
Input

All 45 trained models and a summary of every stock

Operation

Upload them to the Hugging Face Hub; a FastAPI server on a Hugging Face Space loads them once at start-up

Output

/tickers (public) and /predict/<ticker> (needs a login token)

  • Normal accounts get 5 predictions; premium accounts have no limit.
  • Models are kept in memory, so a prediction does not reload anything.

Flow: all_models.pkl + tickers_summary.json >> hf_hub_download >> GET /predict/{ticker}

Stage 06 of 06

Dashboard & login

Done
Input

A signed-in user picking a stock

Operation

Show the price chart, RSI and moving averages, and the model's predicted price and direction

Output

A dashboard on Vercel, with login, register and premium pages

  • My part: the frontend and the login flow, plus the model and metric analysis.
  • Pages without a login token send the user to the login page.

Flow: login.html >> setJWT >> fetchWithAuth("/tickers") >> fetchWithAuth("/predict/<ticker>") >> chart

Results so far

The deployed LQ45 models are not evaluated: they are trained on all 5 years with no held-out data. The only scores are from the 6-stock prototype, and they have no baseline to compare with.

  • 0.66 – 0.91 backtest R², Linear Regression, 6 US stocks On the last 20% of days, the model explained most of the price movement 14 days ahead, but this is a price level, which is easy to explain. Prototype only (not the LQ45 app): AMZN 0.66, META 0.71, MSFT 0.75, AAPL 0.79, NVDA 0.84, GOOGL 0.91. No naive baseline was measured. Source: StockPredictionProject/AOL_ML_LR/AOL_ML_LR/Model2.ipynb
  • 45 LQ45 stocks, one model each Every stock in the index gets its own small model, trained on fresh data each time the Colab script runs. 5 years of daily Yahoo Finance data per stock Source: colab/lq45_training.py

What I learned

  • Linear Regression could not adapt when a stock changed direction sharply, and predicting the raw price makes errors grow with the price. The team's next step was to predict percentage returns instead.
  • Rupiah error (MAE) is unfair across stocks: IDX tick sizes run from Rp1 to Rp25, so an expensive stock shows a far bigger error for the same percentage miss. R² is the fairer comparison.
  • SVR and XGBoost scored negative R² on most stocks: tree and kernel models only predict inside the price range they saw, so a new price high gives a flat line.

What's next

  • Predict percentage returns instead of the raw closing price.
  • Move to a sequence model (LSTM) to capture momentum over time.
  • Fix data bugs found in user testing, such as ADRO showing a P/B of 18,176x.
  • Add the features testers asked for most: paper trading, a timeframe selector, CSV / Excel export and a ticker search bar.
