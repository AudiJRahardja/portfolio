Fruit Ripeness Detection

Classical computer vision (GrabCut, colour and texture features, SVM) that classifies bananas, oranges and strawberries as unripe, ripe or rotten.

May – Jun 2026

Live demo (opens in a new tab)Code (opens in a new tab)

The problem

Fruit ripeness is still mostly checked by eye, which is slow, subjective and leads to food waste. Deep learning needs a lot of labelled data and computing power. We tested whether a classical, explainable computer-vision pipeline is good enough to sort fruit into unripe, ripe and rotten.

My part

Contributed to the pipeline, preprocessing and results analysis.

How it works

7 stages. Pick a stage to see what goes in, what happens and what comes out. Arrow keys move between stages.

Stage 01 of 07

Pick classes

Done
Input

The Kaggle "Fruit Ripeness Dataset": 7 fruits × 3 ripeness levels, 800 images per class

Operation

Keep three fruits that differ clearly in shape and colour, at all three ripeness levels

Output

9 classes: banana, orange and strawberry, each unripe, ripe or rotten

  • Images come with varied lighting, viewing angles and backgrounds.
  • Split 70 / 30 into train and test.

Flow: fruit-ripeness-dataset >> filter 9 classes >> train / test split

Stage 02 of 07

Preprocess

Done
Input

Raw fruit photos of any size

Operation

Resize to 128 × 128, convert to grayscale and apply a 5 × 5 Gaussian blur

Output

Same-size, smoothed images ready for segmentation and features

  • A fixed size keeps the feature extraction stable.
  • The blur removes small noise and visual variation before texture is measured.

Flow: cv2.resize(128, 128) >> cvtColor(BGR2GRAY) >> GaussianBlur(5, 5)

Stage 03 of 07

Cut out fruit

Done
Input

The resized colour image

Operation

Run GrabCut from a bounding box to separate the fruit from the background, then take its contour

Output

A binary fruit mask, plus two shape features (aspect ratio and extent)

  • Colour and texture are measured only inside the mask, so the background does not leak into the features.
  • If GrabCut finds no fruit, texture is measured on the whole grayscale image instead.

Flow: cv2.grabCut(rect) >> mask2 >> findContours >> aspect_ratio, extent

Stage 04 of 07

Extract 47 features

Done
Input

The image and its fruit mask

Operation

Measure colour in HSV and LAB, an 18-bin hue histogram, GLCM texture and LBP micro-texture

Output

One 47-number vector per image: HSV 6, LAB 5, hue histogram 18, GLCM 6, LBP 10, shape 2

  • HSV catches the colour itself (green unripe, yellow or red ripe, dark brown rotten); LAB separates lightness from colour, so lighting matters less.
  • The hue histogram catches two-colour fruit, like yellow with brown patches.
  • GLCM (contrast, correlation, energy, homogeneity, dissimilarity and ASM, at 1, 3 and 5 pixels) and LBP describe surface texture.

Flow: hsv_feats + lab_feats + h_hist + graycoprops + local_binary_pattern + shape

Stage 05 of 07

Train SVM

Done
Input

Feature vectors of the training images

Operation

Standardise every feature, then train an RBF-kernel SVM (one-vs-one) tuned with GridSearchCV and cross-validation

Output

A trained SVM and scaler, saved for the server

  • Grid: C in 0.1, 1, 10 and gamma "scale" or 0.001.
  • Compared against a Random Forest during the experiments; the SVM did better.

Flow: StandardScaler >> GridSearchCV(SVC(kernel=rbf)) >> fruit_svm_model.pkl

Stage 06 of 07

Evaluate

Done
Input

The held-out test images

Operation

Compute precision, recall and F1 per class, plus a confusion matrix

Output

89.82% accuracy and macro-F1 0.90 on 2,191 test images

  • Ripe banana (F1 0.95) and ripe strawberry (0.94) are easiest; unripe banana (0.80) is hardest.
  • Main mix-ups: unripe banana read as ripe banana (16 images) and rotten orange read as ripe orange (18).

Flow: predict(test) >> classification_report >> confusion_matrix

Stage 07 of 07

Web demo

Done
Input

A photo upload or a live camera frame

Operation

The web page sends the image to a Flask API that runs the same feature extraction and the SVM

Output

The predicted fruit and ripeness, with a confidence score

  • The Flask API runs in a Docker Hugging Face Space; the static page is on Vercel.
  • If the server is down the page shows an error instead of guessing.

Flow: upload / camera >> POST /predict >> extract_features_from_array >> SVM >> result

Results so far

The report says the SVM beat a Random Forest, but gives no Random Forest numbers, so there is no baseline score to show next to it.

  • 89.82% test accuracy, 9 classes Gets about 9 in 10 fruit photos right: the fruit and how ripe it is. Group project; 2,191 test images, about 240 per class; macro-F1 0.90 Source: Final Project ComVis_KEL1_AudiJoelRahardja/Final Report ComVis.docx (1).pdf
  • 0.95 F1, ripe banana (best class) Bright yellow is easy to recognise. Ripe strawberry close behind at 0.94 Source: Final Project ComVis_KEL1_AudiJoelRahardja/Final Report ComVis.docx (1).pdf
  • 0.80 F1, unripe banana (hardest class) Green and half-yellow bananas look alike, so these get confused with ripe ones. Recall 0.78 Source: Final Project ComVis_KEL1_AudiJoelRahardja/Final Report ComVis.docx (1).pdf
  • 0.88–0.91 F1 for rotten fruit, all three types Brown patches and broken texture make rotten fruit easy to catch, which matters most for sorting. Rotten banana, orange and strawberry Source: Final Project ComVis_KEL1_AudiJoelRahardja/Final Report ComVis.docx (1).pdf

What I learned

  • Colour alone is not enough: unripe and ripe bananas overlap in colour, which is where most errors are. Texture (GLCM, LBP) and the hue histogram help separate the stages.
  • Segmentation choice matters. An earlier version cut the fruit out with Otsu thresholding (the slides); the final model uses GrabCut so colour and texture come from the fruit, not the background.
  • Hand-made features are explainable: when a class is misread, you can look at the exact colour or texture numbers that caused it.

What's next

  • Test on real photos with varied lighting, angles and backgrounds; the dataset is fairly controlled (from the report's limitations).
  • Cover more fruit types (from the report's future work).
  • Try combining the SVM with other models, or with deep features, while keeping it explainable (from the report's future work).
