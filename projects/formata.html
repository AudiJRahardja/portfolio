Formata

"Check your skripsi before your supervisor does": a startup concept for automatic thesis formatting and citation checks.

Oct – Nov 2026

Live demo (opens in a new tab)Code (opens in a new tab)

The problem

Indonesian students writing a skripsi lose revision rounds with their supervisor over format: margins, fonts, spacing, chapter and page numbering, and references that do not match the source. Every university, and often every faculty, has its own guide, and checking by hand takes late nights before each submission.

My part

Product idea, pipeline and technical architecture: planned citation checking through Crossref, and how the margin and formatting checks would work.

How it works

6 stages, 3 still planned (dashed). Pick a stage to see what goes in, what happens and what comes out. Arrow keys move between stages.

Stage 01 of 06

Pick rules

Done
Input

The student's university guide or their lecturer's own rules

Operation

Choose a format template and a citation style, or type the margins, font and line spacing by hand

Output

The rule set the draft will be checked against

  • The demo offers a generic Indonesian skripsi template, four university templates and a custom option.
  • Citation styles: APA 7, IEEE, Harvard or Auto.
  • A library of templates per university and faculty is planned as the core of the product.

Flow: choose_template >> choose_style >> custom_rules

Stage 02 of 06

Upload draft

Done
Input

The thesis draft as a Word file

Operation

Drag and drop or pick the file; the page accepts only .docx up to 20 MB and asks which checks to run

Output

A file plus the chosen checks: format, citations (basic or in-depth) and plagiarism

  • A file that is not .docx gets a clear message to re-save it from Word.
  • Citation checking has a free basic level and a paid in-depth level, matching the freemium plan in the business model.

Flow: FileDrop >> choose_checks >> review_summary

Stage 03 of 06

Parse document

Planned
Input

The uploaded .docx file

Operation

Planned: read the page setup, styles, headings, page numbers, captions, in-text citations and reference list

Output

A structured outline of the draft that the checks can run on

  • Planned. In the demo this stage is simulated: a timer steps through "Reading document" and no file is read.
  • The business model lists the document parser as a key resource.

Flow: read_docx >> extract_layout >> extract_headings >> extract_references

Stage 04 of 06

Format checks

Planned
Input

The parsed draft and the chosen rule set

Operation

Planned: compare what the draft has with what the rules expect, one rule at a time

Output

Pass, check or fail for each rule, with the place it failed and how to fix it in Word

  • Planned checks: paper size, margins, body font, line spacing, alignment, indent, chapter titles, subheading numbering, page numbers, front matter and caption position.
  • Example from the sample report: "Left margin: expected 4 cm, found 3 cm (Chapters 2 to 3)".

Flow: load_rules >> check_layout >> check_typography >> check_numbering >> check_captions

Stage 05 of 06

Citation lookup

Planned
Input

The reference list and the in-text citations

Operation

Planned: look up each reference in Crossref and compare title, authors, year and DOI; also match in-text citations against the reference list

Output

Each reference marked verified, partial match (with what differs) or check manually

  • Planned. Crossref was chosen as the metadata source; OpenAlex, Semantic Scholar and Indonesian indexes (Garuda, SINTA) are listed as possible extra sources for local journals.
  • The basic level only matches in-text citations with the reference list: citations missing from it, and entries never cited.
  • Books and local journals that Crossref does not have are flagged for a manual check instead of being called wrong.

Flow: split_references >> crossref_lookup >> compare_metadata >> match_in_text

Stage 06 of 06

Report

Done
Input

The check results

Operation

Show a summary, then tabs for format, citations and plagiarism

Output

A pass / fail report the student can work through before seeing their supervisor

  • The report page is built, but it always shows a fixed sample report, not results from the uploaded file.
  • Interface in Indonesian and English.

Flow: report/sample >> FormattingTab >> CitationsTab

Results so far

What I learned

  • Crossref does not cover everything a skripsi cites: Indonesian books and local journals are often missing, so the design has a "check manually" result instead of marking those references wrong.
  • The business model needs the terms of use, rate limits and coverage of each metadata API checked before the product depends on it.
  • The template library per university and faculty is the main advantage and also the most labour-intensive part to build and keep up to date.

What's next

  • Build the real document parsing, format checks and Crossref citation lookup (planned; simulated in the demo).
  • Build and maintain the library of university and faculty templates.
  • Check that students are willing to pay, since free alternatives exist (Word templates, Mendeley, Zotero).
